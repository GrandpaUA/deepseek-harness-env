«Редактор як у VS Code» для DSH Web: три варіанти

Ви переїжджаєте з консолі VS Code у DeepSeek Harness Web GUI. Нижче — три реальні способи закрити прогалину «редактор коду + файлове дерево + git у GUI». Усі скріншоти взяті з README відповідних репозиторіїв на GitHub і завантажені локально (img/); жодних вигаданих посилань.

Варіант 1 — Легкий: better-er/dsh-classic-coding1 плагін · клієнтський

У веб-розмові DSH праворуч виїжджає панель з Monaco-редактором (той самий рушій, що у VS Code) і лінивим деревом файлів — локальний воркспейс можна редагувати прямо в діалозі, без зовнішнього редактора.

Скріншоти з README

Плюси

  • Мінімальне втручання в GUI: лише дві точки монтування (кнопка сайдбара + overlay-панель).
  • Monaco — той самий редакторський рушій, що у VS Code: підсвітка синтаксису, вкладки кількох файлів, Ctrl+S.
  • Ліниве дерево файлів з фільтрами .git, node_modules тощо.
  • Автоматично адаптується до світлої/темної теми DSH (Monaco перемикається на лету).
  • Без збірки: вихідний код = продукт, жодних npm-залежностей (Monaco тягнеться з CDN).
  • Просте встановлення/видалення однією командою dsh plugin --profile web add github:better-er/dsh-classic-coding.
  • Є демо-відео роботи плагіна.

Мінуси

  • Немає git — тільки файли й редактор.
  • Немає термінала.
  • Це overlay-панель над розмовою (закривається по Esc/масці), а не постійний workbench-шел як у VS Code.
  • Дерево файлів спрощене: перегляд/редагування; повноцінних файлових операцій (rename, drag&drop, контекстне меню) README не обіцяє.
  • Monaco з CDN — для першого відкриття редактора потрібен інтернет.
  • README китайською.

Варіант 2 — Повний workbench: AKS1st/dock + dock-editor, dock-files, dock-gitмодульна серія 1–6 плагінів

VS Code-подібний шел для DSH Web: activity bar, side bar, зона редактора з вкладками, панель і статус-бар (плагін dock), у який «втикуються» функціональні плагіни: файлове дерево, текстовий редактор, git-граф.

У README самого базового репо AKS1st/dock скріншотів немає (перевірено китайську та англійську версії) — вигляд шелу демонструють скріншоти підплагінів нижче, які монтуються всередину нього.

Скріншоти з README підплагінів

Плюси

  • Архітектурно найближче до VS Code: activity bar / side bar / вкладки редактора / панель / статус-бар, стики до країв екрана, плаваючі вікна, збереження лейауту в localStorage.
  • Модульність: ставите лише потрібне (сам dock — чистий шел; +files, +editor, +git — за потребою).
  • Повноцінний git: граф комітів, гілки/теги, merge, stage/commit/push, reset/revert, віддалені операції, пошук кількох репо у воркспейсі.
  • Файловий менеджер як у VS Code: створення/перейменування/копіювання/вирізання/вставка/видалення, drag&drop-імпорт, вставка файлів і зображень з буфера обміну, центр передач із прогресом.
  • Редактор: CodeMirror 6 з підсвіткою, Ctrl+F/H пошук-заміна у стилі VS Code (окремий спливний шар), підтвердження незбережених змін, детект бінарних файлів.
  • Відкритий реєстр ctx.workbench — екосистема розширюється (dock-images, dock-markdown та ін.).
  • Інтерфейс zh/en, безпекові обмеження запису рамками сесійного воркспейсу.

Мінуси

  • Повний комплект — це 4+ окремі плагіни (dock + files + editor + git): більше рухомих частин, ніж варіант 1.
  • Втручання в GUI важке: workbench перебудовує оболонку сторінки (стики, плаваючі вікна, статус-бар).
  • Редактор — не Monaco, а CodeMirror 6: близько до VS Code за хоткеями, але це інший рушій (бандл dock-editor ~1.12 МБ).
  • dock-editor: ліміт 256 KiB на файл — більші відкриваються read-only з обрізаним вмістом.
  • dock-git потребує системного git у PATH.
  • Немає термінала (на відміну від варіанта 3).
  • README переважно китайською (є англійські версії).

Варіант 3 — Важкий моноліт: All3nCN/dsh-better-sidebar-N231 плагін · клієнт + сервер

Повний workbench одним форком dsh-better-sidebar: explorer, редактор, справжній термінал (xterm.js + node-pty), Git-панель, вбудований браузер, фонові задачі та подвійні робочі області зі split-панелями — у VS Code-подібній оболонці з 48px верхньою панеллю та activity rail.

Скріншотів у README немає (перевірено китайську README.md та англійську README_EN.md) — вигляд інтерфейсу неможливо оцінити без встановлення, тому ця секція без зображень.

Плюси

  • All-in-one: дерево файлів + редактор + термінал + git + браузер + задачі — один плагін замість цілої серії.
  • Єдиний з трьох варіантів зі справжнім терміналом (xterm.js + node-pty, реальний shell, reconnect-replay, опційно terminal_* тули для моделі).
  • Передперегляд зображень / Markdown / HTML / PDF / Office прямо у файловій панелі.
  • Подвійний воркспейс: правий сайдбар + нижня панель, перетягування табів для split/merge (навіть між панелями).
  • Git: справжній diff у VS Code-стилі, історія, stage/commit/revert з контекстного меню.
  • Сервісний API ctx.betterSidebar (registerTab / registerFileViewer) для сторонніх плагінів.
  • Лейаут/таби/панелі зберігаються пер-сесія; інтерфейс zh/en.

Мінуси

  • Найважче втручання в GUI: перебудовує весь шел (повноширока верхня панель, activity rail) — розмова й workbench співіснують, але інтерфейс змінюється радикально.
  • Неможливо оцінити вигляд заздалегідь: у README немає жодного скріншота.
  • Форк із власним cadence релізів (npm-скоп @all3cn), src/ і lib/ синхронізуються вручну і «навмисно роз'їхались» (за README: рантайм керується з lib/) — ризик супроводу.
  • Потрібен Node.js >= 20 і серверна частина (node-pty) — важче за суто клієнтські плагіни варіантів 1–2.
  • Моноліт: не можна «дозібрати» лише потрібне, як у dock-серії.
  • Перевірено лише на DSH 0.1.1-rc.2; документація переважно китайською.

Короткий вердикт

Варіант 1 — якщо треба «швидко правити код у розмові» без перебудови інтерфейсу: легкий, з Monaco, але без git і термінала.
Варіант 2 — якщо хочеться саме VS Code-подібний workbench: збираєте з модулів лише те, що потрібно; найкращий git-GUI з трьох; без термінала.
Варіант 3 — якщо потрібно все й одразу (особливо термінал) і ви готові до радикальної зміни оболонки та форк-ризиків; вигляд до встановлення не побачити.
